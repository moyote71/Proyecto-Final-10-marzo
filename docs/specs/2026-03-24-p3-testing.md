# SPEC: QA Strategy P3 (Testing Automation)
**Fecha:** 2026-03-24
**Status:** DRAFT

## 1. Definición del Problema
Hasta ahora, la verificación de integridad se hace 100% manual (QA). No poseemos salvaguardas que prevengan regresiones. Cualquier ingeniero futuro que vuelva a tocar `authController.js` y remueva el emisor de JWT (Cookie) podría romper el SSDLC sin enterarse. Todo código no testeado es legado.

## 2. Herramientas y Framework
**Backend**
- **Test Runner:** `vitest` (Rápido, compatible con Esm).
- **Mocking Exteno:** `supertest` para simular peticiones Express sin levantar puertos reales.
- **Base de Pruebas:** `mongodb-memory-server` para levantar un mongo efímero nativo en memoria (no interactúa ni daña tu DB real en Mongo Atlas).

**Frontend**
- **Ecosistema:** Jest / React Testing Library (`@testing-library/react`).
- **Filosofía:** Testing centrado en el usuario. En vez de evaluar clases internas, evaluaremos *"Si escribo texto aquí y presiono el botón Login rojo, debe salir un Loading..."*

## 3. Alcance Mínimo Viable (MVP)
Para cerrar el pipeline del Backlog P3 no es necesario llegar al 100% de Line Coverage (falso sentido de seguridad). Nos enfocaremos en Coverage Vertical en las 2 barreras más importantes del e-commerce:

1. **Flujo Cero:** `Login` / `Registro`. Testearlo arriba (componente react reaccionando a click) y abajo (Controller disparando query / JWT).
2. **Flujo de Consumo:** `Productos` (Búsqueda exitosa que devuelva un json válido) y visualización del `Carrito`.
